# 多进程

CPU工作就是取指令执行。但是由于一个任务中io指令执行速度慢或者其他原因导致CPU工作时间短，利用率很低。为了解决这个问题，可以并发的执行多个进程。多个进程之间相互切换，同时需要pcb这个数据结构来保存进程的状态，像pc指针和寄存器里面的数据等等。os通过这样切换CPU执行的任务来管理CPU。

用户使用计算机就是创建进程，管理计算机就是管理多个进程。

多进程间的组织：通过pcb和进程状态形成多个队列，放到多个位置。

多进程间的调度和切换：通过调度算法在就绪队列中选择下一个进程，同时和cpu中正在执行的进程参数进行转移和覆盖。

多进程间的相互影响：为了避免多个进程访问对方内存导致程序崩溃，必须进行内存管理，通过映射表将内存映射到不同位置上。

多进程间的合作：通过锁，信号量等操作使得多个进程间相互配合完成任务。

进程 = 资源 + 执行指令序列

进程是资源分配的最小单位，线程是执行任务的最小单位

# 线程

因为进程间的切换涉及到指令序列的切换和资源的切换，为了方便学习，先学习指令序列的切换，也就是线程间的切换。

注意，上面提到的PCB保存pc指针信息只是在单线程中。如果有多个线程，那么pc指针的信息实际上保存在TCB中。

## 用户级线程

每一个线程都有一个栈来保存函数调用等信息。同时有一个 TCB 内存来保存栈的地址信息（ESP）
创建线程时，先申请TCB的内存用来保存栈地址。然后申请栈的内存空间，并将执行函数入栈。
当线程切换时，把 ESP 寄存器的值（栈顶地址）存入 TCB，同时另一个线程的TCB中保存的栈信息覆盖掉ESP 寄存器。
因为用户级的线程，不涉及内核的调用。上面的内存都是在用户态中，操作系统并不知道多线程的存在。这样用户级线程的浏览器，如果某一个线程进行io阻塞，操作系统将切换进程，所有的线程都会卡住。

## 内核级线程

线程依旧有一个栈保存函数地址，但是TCB内存在系统内核中。
操作系统能管理多线程，并且在其中一个阻塞时，自动完成线程切换操作。
PCB和TCB其实都是内核中的一块内存，PCB中通过链表保存线程TCB，TCB中指针指向对应PCB。

从一个栈到一套栈，从两个栈到两套栈。同时有用户栈和内核栈。

多核的优势在于共享 L3 + 共享内存控制器，通信极快；多核的劣势在于所有核抢同一组内存带宽，扩展有限。

多处理器的优势在于各自有独立内存带宽，可线性扩展；多处理器的劣势在于跨 socket 访问很慢。

一个适合共享数据密集的任务，一个适合独立数据分区的任务。 就这么简单。

多核硬件提供了两个东西：
1. 并行执行能力——多进程、多线程都能利用
2. 低成本的共享数据通道（共享 L3 + 统一内存）——只有多线程能用


中断入口：建立用户栈和内核栈的关联，进入中断，压入一些状态

阻塞调度和时间调度

中断出口：调用iret，中断返回


当创建一个线程时，先申请一页内存。创建用户栈和内核栈，将esp分别设为对应地址，并设置好等级。

在线程中执行系统调用函数时，read函数通过glibc 翻译为带着0x80中断信号的代码。通过查看IDT表得知要陷入内核，此时将函数编号赋值给eax寄存器，将CPL设置为内核级。内核栈自动执行压栈操作，将用户栈段寄存器，偏移量，状态，执行的下一条指令等信息压入栈中，为后面从内核栈返回用户栈准备

当在内核态中执行read系统函数时，进入函数中发现磁盘并没有准备好，因此将状态设置为阻塞态，直接调用**schedule**函数切换任务。正常情况下，当任务正常返回结束，且并没有超时，或者被打断状态中时，直接调**ret_from_sys_call**切换回用户态。
```
read()
if(状态为阻塞中) reschedule();
if(超时)    reschedule();
ret_from_sys_cal;

read(){
    if(磁盘准备好，可以读写){
        执行任务
        返回结果
    }
    else{
        将状态设为阻塞中
        schedule() //切换任务
        继续完成任务
    }
    return
}

schedule{
    TCB.esp = ESP;
    newTCB = select. //挑一个用来切换的线程
    ESP = newTCB.esp;
    TSS.ESP0 = 新任务内核栈顶部
}

reschedule(){
    push ret_from_sys_cal;
    schedule;
}

ret_from_sys_cal{
    弹出内核栈中的各种参数
    iret;
}





```

但是如果在函数返回后检查发现超时则调用**reschedule**,即先将ret_from_sys_call压入栈中，然后再调用调度函数schedule切换。这样当再次切回任务执行时，通过schedule的返回可以直接返回用户态。

注意，在系统函数内部调用切换函数时，不能使用reschedule，因为还要保证后面的检查流程正确执行，不能直接切回用户态。

系统调用函数内部的调度函数是正常切换任务，函数外面的则是检查操作。因为不是抢占式的，当任务超时的时刻无事发生。只是在返回后检查操作是否超时。

当进行fork操作时，子进程申请一页内存，申请内核栈。用户栈会暂时和父进程“共用”。当父子进程中的某一个先进行写操作时，会触发缺页。此时父子进程的用户栈会随着写操作的进行慢慢分开。

当子进程执行exec函数时，在陷入内核时，会将返回用户栈的部分信息替换掉。直接有一个新的栈。
