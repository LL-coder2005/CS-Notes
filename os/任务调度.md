# 任务调度



为了保证cpu轮转调度多个任务顺利执行，需要设计一个好的任务调度算法。

首先是最基本的先来先服务算法（FCFS），根据任务到达的时间来排队等待执行。优点是简单，缺点是无法应对复杂情况，无法保证响应时间和周转时间（任务到达 到 任务完成的时间）。

- 第一种算法：在此基础上为了保证平均周转时间最小，使用短任务优先算法（SJF）。将短的任务向前排。但是如果有源源不断的短任务等待执行，长时间的后台任务将会处于饥饿状态，即没有机会执行。

- 第二种算法：为了保证每个任务都有机会执行，使用时间片轮询算法（RR），为每一个任务分配时间片，时间片用完后即自动切换。优点是每个任务公平。缺点是频繁切换可能导致系统内耗时间上升，响应时间下降。这对于追求响应时间的前台任务不好。
- 第三种算法：优先级算法，为每一个任务分配一个优先级。任务可以分为IO约束性任务和CPU约束性任务。IO约束性任务指任务会进行频繁的IO操作，CPU任务指在后台长时间运算某一个任务。在分配优先级时，应该将IO约束任务的优先级调高。



前台任务追求响应时间快，后台任务追求周转时间快。因此可以分为两个任务队列，每一个任务队列以短任务优先为核心保证周转时间，同时为了保证公平性分配时间片，最后可以把前台任务的优先级稍微调高一点。



在实际的Linux 0.11 调度函数中，使用counter 同时表示时间片和优先级。每次遍历任务队列选出就绪并且counter最大的任务开始执行，执行期间counter作为时间片递减。如果就绪的任务counter 均为 0 ，则重置每一个任务的counter = counter >> 1 + p(初始值) 。这样操作可以使得io阻塞任务在下一次任务调度中优先级上升，变相的使得前台任务优先级上升。同时后台任务不断轮询的过程中也近似于SJF。

值得注意的是，这个SJF是指占用CPU的时间长短。频繁的io操作使得占用CPU时间短，优先级更高。

这种模式非常的简单，同时比较好的折中了多种任务。但还是有一些缺陷

1. 如果同时有前台任务和后台任务，前台任务在开始时就io操作休眠。后台任务执行很短时间后时间片耗尽，触发重新分配。后台任务的counter就会很小。无法长时间执行连贯任务。
2. 由于收敛特性，前台任务在极限情况下无法领先后台任务太多。还是会被后台任务抢占CPU
3. 在特殊情况下，初始值过大导致溢出，使得counter变为负数。出现bug。
